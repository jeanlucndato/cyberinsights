Objectif Principal : Maîtrise des IDS/IPS en Environnement Réel

Ce projet est une véritable cyber range personnelle, conçue pour explorer en profondeur l'interaction complexe entre les systèmes de détection d'intrusions (IDS) / de prévention d'intrusions (IPS) et les techniques d'attaque modernes. L'intégration de Snort avec un pare-feu robuste comme PFsense permet de simuler des scénarios de sécurité réseau de niveau entreprise et d'affiner les capacités de réponse.

L'objectif est de comprendre non seulement comment les attaquants opèrent avec Kali Linux et ses outils spécialisés, mais surtout comment une infrastructure défensive (Snort sur PFsense) peut les identifier, les journaliser et les bloquer. Ce cycle continu de Red Team (attaque) et Blue Team (défense) permet de construire une expertise pratique inestimable en Threat Hunting, forensique réseau, et rédaction de règles de sécurité pertinentes.

Le Défi : Complexité et Adaptation aux Évolutions

Déployer un IDS/IPS efficace comme Snort sur un pare-feu hautement configurable tel que PFsense présente plusieurs défis : la gestion fine des règles pour minimiser les faux positifs, l'optimisation des performances sur des volumes de trafic élevés, et l'adaptation constante aux nouvelles techniques d'évasion et menaces émergentes. Il faut également garantir une visibilité complète sur le trafic chiffré et non chiffré.

La Solution : Une Approche Systémique et Itérative

Ce projet résout ces défis par une approche systémique. PFsense assure la segmentation réseau et la gestion du trafic, tandis que Snort effectue l'inspection approfondie des paquets. L'utilisation de Kali Linux pour la simulation d'attaques permet des tests itératifs et un affinement précis des règles IDS/IPS. Cela inclut l'analyse des logs, la corrélation d'événements et la réactivité face aux alertes en temps réel, forgeant une expertise en ingénierie des règles de sécurité.

Architecture & Déploiement du Laboratoire IDS/IPS

Découvrez la topologie réseau complexe et les étapes essentielles pour la mise en place de ce projet avancé de détection d'intrusions.

Topologie Réseau Virtuelle – Le Cœur du Lab
  • Pare-feu / Routeur OPNsense :
    Élément central du réseau, gérant les interfaces WAN (Internet simulé) et LAN (réseau interne sécurisé). Il intègre le module Snort pour assurer la sécurité périmétrique et inspecter le trafic en temps réel.
  • Serveur IDS/IPS (Snort) :
    Intégré dans OPNsense, il fonctionne en mode inline (IPS) pour bloquer activement les menaces, ou en mode promiscuous (IDS) pour détecter passivement les attaques. Il analyse les paquets en profondeur pour identifier les signatures malveillantes.
  • Kali Linux (Attaquant) :
    Machine virtuelle connectée au LAN, utilisée pour simuler des attaques variées (scan de ports, exploitation de failles, injections) afin de générer du trafic malveillant et tester la réactivité du système de défense.
  • Machines Cibles Vulnérables :
    VMs comme Metasploitable ou Windows Server vulnérable, hébergées sur le LAN. Elles servent de cibles réelles pour les attaques, permettant d’évaluer l’efficacité de Snort et d’observer les alertes générées.
  • Outils d’Analyse (Wireshark, ELK Stack) :
    Wireshark permet l’analyse forensique des paquets capturés (PCAP), tandis qu’un système de centralisation des logs (ELK Stack) agrège les alertes de Snort et OPNsense pour une visualisation corrélée et un threat hunting efficace.
Étapes Clés du Déploiement et de la Configuration
  1. 1. Installation d’OPNsense :
    Déploiement de l’OS sur une machine virtuelle ou un serveur dédié, avec configuration des interfaces réseau et des services de base.
  2. 2. Intégration de Snort ou Suricata :
    Activation du module IDS/IPS dans OPNsense, sélection des règles (Community, VRT, Emerging Threats), et configuration du mode IDS ou IPS sur les interfaces à surveiller.
  3. 3. Déploiement de Kali Linux & Cibles Vulnérables :
    Installation de la machine Kali pour simuler des attaques, ainsi que des cibles vulnérables sur le réseau interne (LAN) protégé par OPNsense.
  4. 4. Création de Règles de Pare-feu :
    Mise en place de règles de filtrage dans OPNsense pour contrôler le trafic entre les zones réseau et vers l’extérieur, en coordination avec Snort.
  5. 5. Rédaction de Règles Snort Personnalisées :
    Développement de règles spécifiques pour détecter des comportements malveillants, des portes dérobées ou des failles exploitées par Kali, avec ajustement pour réduire les faux positifs.
  6. 6. Exécution de Scénarios d’Attaque :
    Lancement d’attaques depuis Kali Linux pour tester la robustesse du pare-feu et des règles Snort, suivi d’une analyse des alertes générées dans OPNsense et via Wireshark.
  7. 7. Mise en Place de la Journalisation Centralisée :
    Configuration de Syslog ou d’un agent de collecte pour envoyer les logs d’OPNsense et Snort vers un SIEM ou une stack ELK, permettant une corrélation des événements et une visualisation des menaces.

Kali Linux – IP Dynamique & Règles Snort

Machine Kali Linux utilisée pour simuler des attaques dans le laboratoire IDS/IPS.

Dans ce laboratoire, Kali Linux est configurée pour obtenir une adresse IP dynamique toutes les 50 secondes afin d’éviter sa détection par Snort. Cela permet de simuler un attaquant qui change d’identité réseau fréquemment.

Script Bash pour renouveler l'IP via DHCP : 

# Ce script libère l'IP actuelle et en demande une nouvelle toutes les 50 secondes
while true; do
  sudo dhclient -r eth0        # Libère l'adresse IP actuelle
  sudo dhclient eth0           # Demande une nouvelle IP via DHCP
  sleep 50                     # Pause de 50 secondes avant le prochain changement
done

Pour une anonymisation plus avancée, Kali peut utiliser Tornet, basé sur le réseau Tor. Cela permet de masquer l'adresse IP réelle en redirigeant le trafic via des nœuds Tor.

Configuration de Tor et Proxychains : 

# 1. Installer Tor
sudo apt update
sudo apt install tor

# 2. Installer Proxychains
sudo apt install proxychains

# 3. Modifier le fichier de configuration
sudo nano /etc/proxychains.conf
# Ajouter ou vérifier la ligne suivante à la fin :
socks5 127.0.0.1 9050

# 4. Lancer Tor
sudo service tor start

# 5. Exécuter une commande via Tor
proxychains curl https://check.torproject.org

# 6. Changer d'identité Tor manuellement
sudo service tor restart
